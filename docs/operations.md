# 维护、发布、回退与备份

本项目由仓库维护者负责代码、依赖、技能和知识变更；示例数据中的“IT 服务台”是虚构责任人，不代表已配置真实值班团队。上线到真实组织前需建立明确 owner 和值班流程。

## 日常维护

| 变更 | 必做验证 | 责任 |
|---|---|---|
| 技能版本 | 工具许可、审批要求、回归评测通过后激活 | 技能负责人 + 审核人 |
| 知识发布 | 来源、适用版本、权限、云许可、检索命中和引用 | 文档责任人 + IT 审核人 |
| 模型/提供商升级 | 记录型号快照，dev 回归、故障注入、用量字段契约 | 项目维护者 |
| embedding 型号/维度 | 重建索引；严禁混用旧向量 | 项目维护者 |
| 依赖升级 | 小批量变更、Python 测试、前端 build、启动检查 | 项目维护者 |

建议发布记录写明 commit、Python/Node 版本、模型名、价格日期、评测报告路径及已知失败；不要仅写“模型更聪明”。跟进上游废弃接口时优先增加适配契约测试，避免静默切换请求格式。

## 启动与健康检查

- 本地服务仅绑定回环地址，使用一个 backend worker。不要用多个 worker 共享 Qdrant local 目录。
- `python -m deskpilot.cli init` 仅本地初始化演示资料；`check` 在配置齐全时执行少量付费连接检查；`serve` 启动 API；`index-cloud` 显式建立付费云向量索引；`export-audit` 导出脱敏审计。
- `/api/health` 用于存活检查；`/api/config/status` 用于能力与缺项检查。
- 401/403、429、超时、维度错误、预算不足、索引失败要在任务/运维页面可见，不能只写后台日志。
- 排查日志时只保留脱敏错误类型、运行 ID、请求阶段和时间，不复制凭据或整份内部文件。

## 备份

演示数据位于 `.env` 的 `DATA_DIR`，默认 `data/`。备份前停止前后端进程，避免 SQLite WAL、检查点和索引处于不同时间点。备份整个数据目录及部署时的代码版本记录，不单独拷贝一个正在写入的 SQLite 文件。

```powershell
# 停止服务后，在仓库根目录执行；目标目录必须是新的备份目录
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$target = Join-Path (Get-Location) "backups\$stamp"
if (Test-Path -LiteralPath $target) { throw 'Backup target already exists' }
New-Item -ItemType Directory -Path $target | Out-Null
Copy-Item -LiteralPath '.\data' -Destination $target -Recurse
```

如果设置了自定义 `DATA_DIR`，把源路径换成已核对的绝对路径。`.env` 含凭据，应由使用者单独通过安全方式保管，不进入公开备份或 GitHub artifact。备份中可能有已删除内容的旧副本，保留周期和备份销毁需另行管理。

恢复先复制到新的数据目录并指向新的 `DATA_DIR`，保留原数据；验证启动、工单状态、记忆删除状态、文档权限、引用和检查点，再切换使用。索引可重建，但不能把重建当作恢复权威数据。

## 回退

1. 停止新版本，保留故障运行 ID 和脱敏日志。
2. 技能问题优先激活最近一个已通过评测的版本；知识问题撤回错误版本，审核后恢复适用版本。
3. 应用回退到明确的已验证 commit，并使用相匹配的数据备份副本。不要默认旧代码能读所有新数据结构。
4. embedding 回退需恢复或重建匹配索引。价格和模型也写入回退记录。
5. 执行关键工单、ACL、来源、记忆删除与预算测试，确认后再恢复演示。

## 记忆与删除边界

任务状态、个人确认偏好、团队共享知识不是同一种数据。个人偏好删除后，之后的运行和恢复路径不得从旧摘要或缓存重新注入该偏好；团队知识发布需审核。检查点和审计为历史记录，备份与已发送供应商的请求不因本地删除自动撤销。不要宣称已经完成法律意义上的全链路彻底删除。

## 生产化仍缺什么

真实身份与 SSO、服务间认证、真实角色目录、密钥托管、隔离执行环境、完整 DLP、不可篡改审计、数据保留策略、灾备恢复演练、并发与负载测试、真实连接器最小权限、租户隔离及法律/合规评估。当前演示会话、正则检测和 SQLite 记录不能替代这些控制。
