# 记忆、续办与上下文

[English](en/memory-design.md) · [中文首页](../README.zh-CN.md)

DeskPilot 不把所有聊天永久塞进提示词。SQLite 的工单和运行记录是任务事实来源，LangGraph 检查点用于恢复执行；个人偏好只在用户确认后保存；团队经验必须转成候选知识并审核发布。

## 每次运行重新构造上下文

- 保留当前任务的最初请求，避免只看最近几轮后忘记原始故障。
- 保留最多 8 条用户自述的处理进度，例如“已经重启客户端，还是 809”；它们是用户报告，不自动变成系统验证结论。
- 补充最近 4 轮授权且有效的对话，不把整个历史无界复制。
- 纳入最多 3 条仍有效的已确认个人偏好；工单还会带入当前标题、描述、状态和解决记录。
- 当前技能的版本和已审核要求参与上下文；技能不能覆盖工具授权或来源约束。

跨会话续办应选定原工单/会话标识。相同浏览器身份的新话题不会自动继承任意其他人的工单；跨用户访问仍受服务端身份和所有权检查。

## 防止删除后复活

每次构造上下文都重新核验来源和个人记忆 revision。检查点中的旧文本不能直接充当当前聊天历史。偏好删除或修改后，依赖旧 revision 的历史答案失效，不再被当作有效上下文或有效历史回答继续展示。

知识撤回、版本切换、权限和云许可改变后，相关来源也需重新判断。旧摘要、缓存和持久化状态不能绕过当前规则。个人偏好不能未经审核自动写入团队知识。

本地失效不等于抹除所有痕迹：备份、审计和第三方已经收到的请求有不同生命周期。项目不宣称已经撤回外部请求或完成法律意义上的全链路删除。

## 实验与限制

[实际记忆实验报告](reports/memory-baseline.md)比较 20 个虚构任务、每个 11 轮，并包含 20 次同一进程内关闭并重建 DeskService 的恢复检查；这不是机器重启或进程崩溃测试。报告中的输入 token 是确定性估算，字符串事实保留是程序检查，**不是模型理解准确率、真实问题解决率或供应商实际账单**。

请优先阅读报告的具体分母和边界。尚未进行真实模型的全历史对照试验时，不把上下文估算减少直接写成 API 费用减少；摘要/提取调用本身的成本在未来真实实验中也必须计入。
